  2. **R-F 长按快捷菜单**：长按今日习惯卡片弹出菜单——查看详情 / 编辑习惯 / 跳过今天（或取消跳过）/ 补签到昨天（尊重 `allow_backfill`，仅昨日未完成时可用）；需提供视觉按压反馈，桌面端兼容右键或长按 500ms
  3. **R-G 快速输入防丢+预填**：快速输入框失焦改为自动保存（非空时）；打开时预填该习惯上一次数值（经 T1 的 `?habit_id=&limit=1`）
  4. **R-E 列表重排动画**：打卡完成后卡片在「未完成→已完成」重排时用 FLIP 平滑位移（复用现有 `ease-soft` 曲线），不得引重依赖库
  5. **R-B 庆祝时刻**：当日全部完成时全屏彩带庆祝（Canvas 轻实现或 CSS 方案，自研不引库）+ 完成文案；同一自然日只触发一次（本地记忆已庆祝日期）
  6. **R-C 昨日遗漏提醒**：首页顶部提醒条「昨天还有 N 项未完成」，展开列出昨日未完成习惯（排除已跳过、排除 `allow_backfill=false`），点击直接弹出昨日日期的 RecordDialog
  7. **R-D 每日激励语**：hero 卡片内置语料库（≥30 条）按日期哈希轮换，风格与「记录坚持」主线一致

- 发现的问题（交主控决策，不擅自改）：
  1. **跳过会吞掉当日已有记录的数值（T1 既有语义，UI 落地后用户可感知）**：对已打卡/已记录的习惯跳过 = 原位置位转换（数值清空、is_completed=false），取消跳过后数值不恢复（回到空记录）。合同如此设计（T1 冻结），但建议主控评估是否在 done_today 时弹确认（当前实现已将菜单「跳过今天」在 done_today 时置灰，风险已收敛；若用户坚持要从完成态转跳过，可先删记录再跳过）。
  2. **快速输入的 Enter 提交路径未能在浏览器证实**：IAB 自动化按键事件不可靠（fill/点击均正常），Enter 隐式提交是标准浏览器行为且存按钮/失焦两条路径已实测通过；建议主控联调时顺手手测一次 Enter。
  3. **`CardMenu` 键盘可达性只做了半套**：有 role=menu/menuitem + Esc 关闭，但无焦点陷阱、无方向键导航、卡片本身无键盘唤出菜单的入口。纯键盘用户无法触达「跳过」。建议后续卡统一做菜单键盘导航（涉及组件通用化，超出本卡范围）。
  4. **预填用 `limit=3` 而非合同的 `limit=1`**：需要滤掉跳过行取最近真实数值，1 条不够；属合同参数的合理放宽（T1 合同写「两个参数可组合」，行为一致）。
  5. **CSV 值不转义（T1 遗留③）本卡未处理**：涉及导出逻辑（local/ 禁区），保持交后续卡。
  6. **测试数据补种发现**：直调 `habitApi.create` 不传 `is_active` 时字段为 undefined，习惯被首页过滤（UI 表单恒传默认值，无用户路径可达；如主控认为值得防，可在数据层 create 归一化，属 local/ 禁区未动）。
