# T1 跳过保护数据层

- 状态：待实现
- 目标：为打卡记录引入「跳过」状态——用户状态不好可标记跳过，不打卡但不断连续天数。本卡只做数据层 + 纯逻辑 + 统计口径，不做任何 UI（UI 由 T2 消费）。背景：用户连续天数是核心激励，状态差的日子被迫断签会打击坚持意愿。

- 接口合同（冻结，T2 依赖这些对外形态）：
  1. **存储**：`StoredRecord` 新增 `is_skipped: boolean`（`local/db.ts`）。旧记录无此字段一律视为 `false`，**不升级 DB_VERSION**（保持 2：不加新索引，记录本就全量内存过滤）
  2. **记录 API**（`api/client.ts` 门面形态不变）：
     - 创建跳过：`api.post("/records", { habit_id, record_date, is_skipped: true })` → 生成 `is_completed=false`、无数值的跳过记录
     - 取消跳过：`api.delete("/records/{id}")`（与现有删除语义一致，删除后该日期可重新记录）
     - 同一 habit+date 至多一条有效记录：对已有记录的习惯执行跳过时，由 T1 决定置位或替换，但必须保证结果满足「is_completed=false 且 skipped 生效」；取消跳过后该日期回到可重新打卡状态
  3. **查询 API**：`api.get("/records?on_date=YYYY-MM-DD")` 返回的 `HabitRecord` 含 `is_skipped`（T2 靠它排除昨日已跳过项）；新增 `api.get("/records?habit_id=X&limit=N")` 按日期倒序返回该习惯最近 N 条（T2 快速输入预填用），两个参数可组合、均向后兼容
  4. **视图类型**（`types.ts`）：`HabitRecord.is_skipped: boolean`；`TodayItem.skipped_today: boolean`；`TodayItem.record.is_skipped: boolean`
  5. **streak 语义**（`local/habitLogic.ts`）：`dailyStreaks` 升级接受跳过集合，跳过日为连续性「桥接」——current 与 longest 都跨过跳过日延续（完成-跳过-完成算连续 3 天）；`weeklyGoalStreaks` 不变（weekly_count 习惯无跳过概念）
  6. **统计口径**（`local/stats.ts`，全部跳过感知）：
     - `todayDashboard`：跳过日不计入 `scheduled_count` 分母、不算 `done_count`、不算「待完成」；item 上带 `skipped_today`
     - `overview` / `trend` / `getHabitStats`：expected 分母排除跳过日，完成率只反映真实执行
     - `calendar` / `yearHeatmap`：跳过日视同 empty（不渲染失败色），`CalendarDay.status` **不新增枚举值**
     - `evaluateAchievements`：跳过不计为完成
  7. **导入导出**：`exportData`/`importData` 完整携带 `is_skipped`（旧备份无此字段导入后视为 false）
  8. 跳过入口的 UI 调用方式（T2 按 T1 的实现落地，形态以 T1 交接摘要为准）
